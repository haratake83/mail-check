# 詐欺メール判定.com

貼り付けたメールの文字情報から、詐欺・フィッシングによく見られる特徴を指摘する静的サイトです。差出人はメールアドレスだけを見ます。SMS、SNS、電話番号の送信元は判定しません。
判定の区分はブラウザ内の JavaScript で行います。画面のコードは、入力した本文やURLを送信も保存もしません。判定のあと、差出人アドレスの登録ドメインだけを当サイトへ送り、公開の登録情報から取得日を調べます。取得から30日以内、31日以上1年未満、1年以上で、結果に足す文章を変えます。どれも詐欺や安全の断定にはしません。取得日が分からないときは文章を足しません。同じ登録ドメインの再照会を避けるため、正規化したドメインと取得日（YYYY-MM-DD）だけを、動いているサーバのメモリに最大7日残します。RDAP の生データや登録者情報は残しません。この取得日は統計・履歴・公開一覧・週間ランキングには使いません。ページを開いた時刻やブラウザの種類などの一般的なアクセス記録は配信会社に残りますが、入力した本文は含めません。

- 表示は **v0.10.5**。判定プロトコルは **v0.10**（スキーマ `0.9-jp-email`）。台帳の中身は 2026-11-06 の凍結版を基にし、SMS送信元の規則は外しています。メールに記載された名前は、お使いの端末の中の判定だけに使い、保存も公開もしません。週間ランキングには、登録ドメインと選択したジャンル・内容だけを、直近7日・10回以上・最大10件で出します。本文内のリンク先ドメインは集めません。本文やURLは統計に使いません。リンク先を別に入力する欄はありません。解説ページの出典は、機関名とページ名、および公式ページへのリンクで示します。
- 注意度の％表示は出していません。画面の結果は4つの判定区分です。
- 精度は**未測定**です。精度・検出率の数値は表示・宣伝しないでください。
- 本実装はプロトコルのブラウザ内サブセットです。稼働ゲート G0/G1b/G3/G4 は未達で、`route_enabled=false`（新規 P16/P17 の S は内部 shadow とし、画面では「要確認」）。本番の判定経路として承認されたものではありません。

## 入力（§2.1）
| 項目 | 必須 | 内容 |

| display_name メールに記載された名前 | 任意 | 判定エンジンへ渡す。送信・保存・公開・URLには出さない |
| subject メールの件名 | 任意 | 判定ルールには使わない。保存も送信もしない。結果と履歴に文字として出すことがある |
| from_email メールに記載されたアドレス | 解析できる@アドレス。電話番号や短い名前は送信元として扱いません。差出人ドメインは、この@より後ろだけ（小文字、末尾ドットなし） |
| body 本文 | 必須（非空） | 本文中のURLと文面は、これまでどおり文字列として見ます |
| sender_genre 送信元のジャンル | 任意・ひとつだけ | 宅配便・配送業者 / 銀行・カード会社 / 通販サイト / 通信キャリア / 官公庁・税務署 / その他・不明。判定の危険度は上げない |
| mail_content メールの内容 | 任意・ひとつだけ | 不在通知・再配達 / アカウント停止・ロック / 未払い料金の請求 / 当選・給付金の案内 / その他・不明。判定の危険度は上げない |
| 本文内のリンク先ドメイン | 本文URLのホストだけ。1通につき同じホストは1回。userinfo・パス・クエリ・フラグメントは出さない。リンクにはしない |
| context_answer | 必須 | 「このメールに心当たりはありますか？」はい／いいえ／わからない（既定: わからない） |

## 結果（§3・§8）
`strong_suspicion`（詐欺メールの疑いが強いです）／`needs_review`（注意が必要です・要確認）／`no_clear_signal`（このツールでは判断できませんでした…＋必須バナー「安全ではありません…」、グレー表示）／`insufficient`（情報が足りず判定できません）。
「本物」「安全」「正規」「問題ありません」という判定は存在しません。`safety_guarantees` は常に false。結果中のURLはクリックできない文字列として表示します。

## 第1段階の追加（スコアは変えない）
画面に、差出人（From）の入れ方、見えるURL文字列の特徴、操作要求に基づく目的候補、「入力を消す」を足しています。危険度・4 verdict・重複排除・ゲートは v0.8 のままです。

- URLの比較キーは正規化した実ホストと、台帳が許す完全一致／サブドメイン境界です。eTLD+1 の一致では公式にも同一運営にもしません。
- Public Suffix List の private 区画は同梱していません。登録境界は不明とし、別テナントを同一運営とは表示しません。パス単位のテナントも証明しません。
- 台帳と一致しても「見える文字列上の一致」であり、実hrefや安全性の確認ではありません。正規ホストに見えるURLの悪用（公開ストレージ、フォーム、文書共有、乗っ取り）は安全の根拠にしません。
- 目的タグは操作要求（命令・誘導＋対象＋手順）だけです。引用・真の否定・注意喚起、単語の並びだけでは付けません。別の句の安心語（「心配ありません」など）では、続く実行要求を消しません。改行や読点で分かれた要求も見ます。「公式アプリ」という自己申告だけでは、APK や構成プロファイルのインストール誘導を除外しません。通常の公式ストア案内だけでは strong にしません。ZIPを開いて内容を確認するだけの依頼は実行誘導にしません。パスワード付きという根拠があるときだけ、その旨を書きます。
- ClickFix や ZIP の実行要求は、従来の集計が N / no_clear_signal のままでも、結果の先頭に実行誘導を出します。4つの判定区分と点数は変えていません。先頭の注意は「強い危険と断定した」という意味ではありません。
- 結果に出す URL はホストまでです。userinfo、パス、query、fragment は長さや記号にかかわらず伏字です。
- device code / OAuth の入力誘導は credential で、実行誘導とは分けます。タグがないことは安全の証明ではありません。
- 統計の案A（端末内）・B（サーバ）・C（ドメイン単位）は未決定のため、実装も保存もしません。`statistics` は `null` です。0件や「この端末のみ」とは表示しません。
- 個別のメールアドレスページや、入力を含む SEO は作りません。

## ブラウザ監査の再実行

Node 22 以降と Google Chrome が必要です。追加の npm パッケージは使いません。

```bash
node js/judge.test.mjs
node js/domain-age.test.mjs
node js/stage1.test.mjs
node js/stage2.test.mjs
node tools/browser-audit.mjs --out /tmp/mail-check-audit
node tools/stage2-browser-audit.mjs --out /tmp/mail-check-stage2
```

監査はローカルの静的サーバに、`vercel.json` と同じ応答ヘッダーを付けてページを開きます。記録するのは Chrome の Network イベント（文書、CSS、JS に加え、画像・フォーム・失敗した要求があればそれも）です。ソースを見て POST が無いことだけでは、非送信の証明にしません。画面の結果と、ページ内で作る結果JSONについて、6桁・英数字の認証コードと和文に直結したURLのパスが残らないこと、ZIPの閲覧依頼と実行要求の主表示の違いも見ます。

この監査は本番 URL もプレビュー URL も見ていません。配信事業者が残す接続記録（IP アドレス、ブラウザの種類、時刻）は、入力した本文を送っていないこととは別です。拡張機能、メモリの物理消去、自動入力の候補、元に戻す履歴の中身は、ページからは確認しきれません。

判定見出しの文字は黒です。強い疑いは赤い枠、要確認は黄の枠、判断できない・情報不足はグレーの枠です。色だけが手がかりにならないよう、見出しの文言で区分を示します。検知規則の変更ではありません。

## 第2段階（履歴と一覧）の範囲

実装しているのは、画面、送る項目の契約、初期状態で無効のアダプタ、合成データだけの投影テストです。実サーバ、外部API、収集、公開、課金、鍵の作成はしていません。`productionReady` と `privacyVerified` は false のままです。

設定がない画面では、履歴も一覧も「現在取得できません」です。件数の 0 や架空の帯は出しません。入力、照会ボタン、同意のない送信、同意を入れた送信のいずれも、このアダプタは通信しません。ブラウザの保存領域へ統計を書く代替もしません。

一覧の並びと少数の除外は `js/stage2-projection.mjs` の契約テストです。このファイルは HTML から読みません。合成の元台帳はテストの中だけにあり、公開ページのスクリプトには入れていません。`js/*.test.mjs` と `tools/` は `.vercelignore` と `vercel.json` の 404 ルートで配信対象から外します。この設定はローカルの再現サーバで確認し、本番やプレビューへは出していません。一覧ページの `noindex` は検索結果に出さない方針であり、ページを開くことを止める制御ではありません。利用規約の下書きには `noindex` を付けていません。

画面側の名前フィルタは、掲載してよいかの安全保証ではありません。掲載前の確認はサーバ側の審査です。

受付の保存（S-STORE）、受付API（S-API）、法務の確定（S-LEGAL）は記録だけです。実装も、外部サービスの選定もしていません。冪等キーのサーバ側再送、保持期限、削除、レート制限（R10–R13）と、統計の本番化（O1）、版表示の整理（O3）は保留です。

累計を主とし、24時間・7日・30日は累計として表示しません。期間を出す場合は、累計ではないと分かるラベルが必要です。数値の閾値、保持期限、鍵、主体IDは、実データ向けに承認された値ではありません。

不足している運用は、受付の保存場所、掲載権限の審査と即時停止、削除とバックアップ、レート制限、配信ログと統計の分離です。外部の収集サービスは選んでいません。

## 既知の制限（homepage担当向け）
- SPF/DKIM、真のリンク先（HTML href）、添付の中身、Reply-To は検証しません。From の一致は認証ではありません。
- スコア用の登録ドメインは Public Suffix List の簡易近似のままです（第1段階の説明では運営者判定に使っていません）。IDNA は URL API 依存です。
- 既存の B07 は「マクロを有効」という文字列があると、否定や引用でも weak になることがあります。第1段階では目的タグにはしませんが、危険度は直していません。
- 既存の A05 は「インストールしてください」を含む通常のアプリ案内でも medium になることがあります。strong には上げていません。目的タグの実行誘導にはしません。
- 本番の計測URL・リダイレクト・scoped_route 台帳は空（G4未達）。未登録の計測URLは普通のURLとして評価します。
- CTA とリンクの対応付けは、本文中のURLと文の対応だけです。リンク先を別に貼る欄はありません。URLへはアクセスしません。
- 差出人の登録ドメインの取得日は、判定のあと公開の RDAP で調べます。30日以内、31日以上1年未満、1年以上のどれでも危険度の区分は変えません。取得日が取れないことは、危険でも安全でもありません。
- E01（ランダム文字列）は研究候補の weak で閾値未校正。.xyz 等のTLDだけでは加点しません（v0.3の独自TLD判定は削除）。
- 台帳は例示で完全一覧ではありません。台帳更新は人手レビューで行い、入力内容から登録しないでください。
